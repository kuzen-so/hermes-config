# 日记工作流 — 格式与分类

## 来源

2026-05-16 会话，用户确认日记格式和笔记分类逻辑。

## 日记格式（用户确认版）

```
2026-05-16

终究还是取消了锚点功能，太容易误触了。

vibecoding 是什么
vibecoding 就是让 ai 根据你的想法写代码...

如何整理碎片化的笔记
Claude 方案是每周分割，Hermes 说放日记就行...
```

### 规则

- 一行一段
- 有目的就第一行写目的，下面写结果
- 重要就加粗
- 不换行分隔，自然流动
- 日期作为标题

### 为什么不用分类

用户原话："每段文字空一行就行了，如果是随口一句话就是一句话，如果有目的就第一行写目的，下面写结果，写完换行就好了。"

### 为什么不用标签

- 额外维护负担
- 等需要跨笔记聚合时再加
- 标题分隔够用

## 语料库定义

**语料 = 有"你"的文件**

| 是语料 | 不是语料 |
|--------|---------|
| 日记 | 教程 |
| 个人计划 | 配置 |
| 有评论的剪藏 | 清单 |
| 个人想法 | 客观概念 |

**判断：** 读一段，有"我"或"我觉得"或"我不喜欢" → 语料

## 碎片处理

用户结论：放日记，不建碎片文件夹。

原因：
- 碎片文件夹 = 垃圾堆
- "每天回顾"比"周末审核"更难坚持
- 维护成本 > 价值

### 周末回顾（可选）

扫两个区块：
- 碎片 → 有没有值得扩展的？
- 想法 → 有没有可以链接的？

随记和任务不用回顾，自然沉淀。

## 98-Logs 已删除

用户原话："日记里啊"

日志类型（系统/操作、错误、行为、变更）全部放日记。
不需要单独 Logs 文件夹。
