# 内容创作项目管理 — 会话洞察

来源：2026-05-16 会话

## 核心问题

用户不是缺工具，是缺**项目边界**。

| 问题 | 表现 |
|------|------|
| 每天忙一堆事 | 小红书被挤掉 |
| 没有项目边界 | 随时被干扰 |
| 感觉重要就做 | 小红书排不上 |

## 解决方案：给项目固定位置

### 1. 时间块

每天固定时间只做小红书：
- 示例：14:00-16:00 只做小红书
- 其他时间不做

### 2. 目标分解

| 时间 | 目标 |
|------|------|
| 第 1 个月 | 500 粉 |
| 第 2 个月 | 1200 粉 |
| 第 3 个月 | 2000 粉 |

每周指标：
- 发布 3-4 篇/周
- 3 个月总篇数 36-48 篇
- 单篇平均涨粉 42-56 粉

### 3. 项目文件模板

```markdown
# [项目名称]

## 目标
- 时间范围：
- 具体数字：
- 截止日期：

## 本周任务
- [ ] 周一：
- [ ] 周三：
- [ ] 周五：

## 选题库
1.
2.
3.
（50 个）

## 数据记录
| 日期 | 标题 | 阅读 | 点赞 | 涨粉 |
|------|------|------|------|------|

## 迭代
-
```

## 习惯型项目 vs 任务型项目

| 类型 | 特点 | 工具 |
|------|------|------|
| 任务 | 做完结束 | 日历、待办 |
| 习惯/项目 | 持续重复，需要坚持 | 需要看进度、streak |

小红书是**习惯型项目**：
- 日历只告诉你"今天要做"
- 不告诉你"你做得怎么样"

## 打卡追踪方案

### 简单方案：Obsidian 表格

```markdown
# 小红书打卡

| 日期 | 是否发布 | 笔记 |
|------|---------|------|
| 5.16 | ✅ | 标题问题 |
| 5.17 | ❌ | 被干扰 |

连续发布：X 天
本月发布：X/Y 篇
```

### App 方案：Streaks（iOS）

- 习惯追踪
- 连续天数
- 统计完成率

## 关键洞察

1. **不要先建碎片文件夹** → 日记足够
2. **不要先买项目管理软件** → Obsidian 表格或 Streaks 足够
3. **先定目标，再定工具** → 没目标，软件只是新玩具
4. **项目边界 = 固定时间** → 不是工具问题，是纪律问题

## 用户风格提醒

- 极简主义，拒绝复杂系统
- 减法优先，能删就删
- 日记是核心，其他都是辅助
- 不喜欢被推着走，需要自主节奏
