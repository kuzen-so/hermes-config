# 小红书图文发布完整工作流

## 本次会话完整案例

**选题**：笔记过千后我悟了：没有AI的笔记系统真的很痛苦

### 文案迭代过程

**用户初稿问题：**
- 开头说教感重（"Obsidian别再手动整理了，让AI来"）
- 工具推荐像说明书（三个工具列参数）
- 结尾辩解感重（"放弃整理不是为了懒"）
- 插件推荐放正文，像技术博客

**修正方向：**
1. 开头直接上痛点故事，不用反问铺垫
2. 工具压缩进故事，或放评论区
3. 结尾用金句收，不解释
4. 正文只讲故事，工具放评论区置顶

**定稿结构：**
```
痛点（2句）→ 顿悟（1句）→ 解决方案（2句）→ 工作流（1句）→ 安全提示（1句）
```

### 配图生成与匹配

**5张图分工：**
| 顺序 | 图内容 | 对应文案段落 |
|------|--------|------------|
| 封面 | "不用整理 / 直接问AI / 笔记的价值是随时能问到" | 核心观点 |
| 图2 | "3000条笔记 / 找一条靠运气 / 分类200小时" | 痛点引入 |
| 图3 | "Obsidian+AI / 丢进去，对话找回" | 解决方案 |
| 图4 | "AI收件箱 / 不想整理的丢进来 / 问AI就行" | 工作流 |
| 图5 | "有问题 / 评论区交流 / 你的笔记怎么整理的？" | 互动引导 |

**废弃图识别：**
- "坟墓or大脑"图混入效率工具系列，主题不符，弃用
- 每张生成后必须用 vision_analyze 确认内容，避免占位符图标

### 评论区运营

**正文不提插件，评论区置顶：**
```
插件推荐：
1️⃣ Claude Sidebar：Claude Code用户必备，开OB自动唤醒Claude
2️⃣ Terminal：直接在OB打开终端，跑任何Agent/CLI，我用的Hermes和Kimi Cli
```

### 关键教训

1. **标题确认后再生成配图** — 本次标题从"真的很难痛苦"改为"真的很痛苦"，配图文字需同步
2. **互动引导图避免客服感** — "看到都会回"→"你的笔记怎么整理的？"
3. **安全提示图可独立生成** — "删之前 / 先扔垃圾桶"作为第6张补充
4. **文件名hash问题** — nanobanana有时会重置文件名，生成后立即重命名
5. **身份优先于工具** — 用户顿悟：工具会过时，身份才是资产。内容重点从"推荐工具"转向"替用户试错后的洞察"
6. **"够了"系列身份锚点** — 表层：替你试过所有捷径的人；中层：发现工具都在骗我干活；底层：你不是缺工具，是缺"够了"的勇气

## 通用检查清单

发布前确认：
- [ ] 标题无歧义、无病句（不超过20字）
- [ ] 正文300-800字，小红书舒适区
- [ ] 配图与文案段落一一对应
- [ ] 无废弃图混入（主题不符、风格不一致）
- [ ] 工具推荐放评论区，正文只讲故事
- [ ] 互动引导用提问式，不用客服式
- [ ] 评论区置顶文案已准备好
- [ ] 标签已选（5-10个，精准+流量组合）
- [ ] 身份一致性检查：内容是否强化"学长/同行者"人设，而非工具说明书
