# Content Factory — AI内容生产系统

## 系统架构

```
voice/     → 读全部，提炼用户风格
clip/      → 按选题关键词搜索相关素材
rule/      → 读全部，套用已验证框架
idea/      → 更新状态（创作中→已发布）
draft/     → 写初稿存这里
```

## 执行流程

### 1. 接收选题
用户输入格式：`写公众号：选题名称` 或 `写小红书：选题名称`

### 2. 自动读取文件
- `cat ~/Documents/Obsidian/10-Work/voice/*.md` → 提炼风格指南
- `grep -r "关键词" ~/Documents/Obsidian/10-Work/clip/` → 找相关素材
- `cat ~/Documents/Obsidian/10-Work/rule/*.md` → 读框架规则

### 3. 生成初稿
根据平台选择框架：
- **公众号**：钩子→痛点→解决方案→步骤→金句收尾
- **小红书**：个人故事→情绪共鸣→经验分享→互动引导

### 4. 去AI味检测
自动标出以下表达：
- 营销体大词：赋能、闭环、打通、底层逻辑
- 替读者说话：「你可能觉得……」「很多人会问……」
- 指令语气：「记住」「一定要」「核心就一句话」
- 虚构数据：「90%的人不知道」
- 独立短句装戏剧感：一句话。一个词。成段。
- 加粗口号金句：真正厉害的人都在……

### 5. 输出到draft/
文件命名：`draft-选题名.md`

## 风格指南（从voice/提炼）

基于用户已发布爆款文章的特征：

### 标题公式
- 「用对X，你的Y瞬间提升！」（Mermaid：14,508阅读）
- 「突发/紧急消息！+ 行动指令」（Notion封禁：5,000+）
- 「从0-1带你了解X」（Notion核心：7,850阅读）
- 必须有硬数字或强烈对比

### 语气特征
- 先下结论再给理由
- 用数字不用形容词
- 拿别的行业逻辑解释当前事
- 不用鸡汤收束
- 自称"小编"但内容硬核
- 步骤化讲解，编号清晰

### 结构特征
- 开头：痛点场景引入
- 中间：步骤化教程，配图说明
- 结尾：互动引导（留言/进群）
- 相关推荐：3篇历史文章

## 使用方法

### 正常流程
用户说："写公众号：AI副业4个月变现10万"

系统自动：
1. 读voice/提炼风格
2. 搜clip/找"AI副业""变现"相关素材
3. 读rule/套公众号框架
4. 生成初稿 → draft/idea-ai副业.md
5. 标出AI味句子

用户审稿、改AI味、发布。

### 用户表达创作困惑/找回语言需求时
用户可能在谈：
- "我不知道自己的语言是什么"
- "我觉得我没有特色"
- "大众需要情绪，但我不知道怎么写"
- "我想找回自己"
- 用户在记录生活、思考情感、探索自我，而非要求"帮我做账号"

此时**不进入写作流程**，而是：
1. 帮用户从日记/对话中提取"有情绪张力的片段"
2. 标记这些片段的**情绪类型**（关系落差、自我审判、顿悟、孤独、愤怒、矛盾、清醒）
3. 展示这些就是用户的"语言"——不是干货，是带着伤口的思考
4. 不强迫用户"敢不敢发"，只问"这段话你想保留吗"
5. 用户想保留 → 存入语料库；不想保留 → 继续写

**关键判断：用户是在"生活/思考"还是在"工作/执行"**
- 用户谈感受、困惑、回忆、情感观、人际关系 → **生活/思考模式**，只听和回应，不给下一步
- 用户说"写公众号""发小红书""选题""变现" → **工作/执行模式**，进入写作流程
- **禁止把生活对话转化为"发一篇吧"**——不是每段思考都需要变成内容

**禁止行为：**
- 不问"敢不敢""能不能""要不要"
- 不用激将法（"直接说""敢发或不敢"）
- 不把用户的思考直接变成"发一篇吧"
- 不把生活记录引导到"做账号"
- 用户要的是被听见，不是被解决

### 选题枯竭流程
用户说："不知道写什么"、"没选题"、"选题荒"

系统自动：
1. 读rule/数据复盘.md → 什么类型爆了
2. 读clip/ → 有什么素材可延伸
3. 读idea/ → 当前选题池状态
4. 给出3-5个具体选题建议

选题来源优先级：
- 已爆类型延伸（最高）
- 素材库延伸
- 热点嫁接
- 旧文翻新

用户选一个，进入正常流程。

### 跨平台需求挖掘法（选题枯竭时扩展）

当用户选题枯竭且现有素材库/历史爆款无法延伸时，启动跨平台需求扫描：

#### 执行流程
1. 确定用户擅长领域（效率工具/内容创作/个人管理/编程等）
2. 去目标平台搜索该领域近期内容，重点看**评论区**而非正文
3. 记录高频问题、痛点、"求教程"类留言
4. 筛选"有人在问但现有回答零散/不完整"的需求点
5. 包装成选题建议

#### 平台优先级
| 平台 | 看什么 | 为什么 |
|------|--------|--------|
| 小红书 | 评论区高频问题 | 用户画像接近，需求真实 |
| 即刻 | 相关圈子讨论 | 高质量用户，付费意愿强 |
| 抖音/视频号 | 小商家广告 | 已验证的变现需求 |
| 知乎 | 高赞问题的补充回答 | 深度内容缺口 |

#### 判断标准
一个需求点值得做成选题，当且仅当：
- 同一问题在多个评论区重复出现
- 现有回答零散、作者自己承认"还没试过""还没搞懂"
- 用户能用已有能力+2小时内整理出解决方案
- 没有人在卖系统化的解决方案（配置包/模板/课程）

#### 输出格式
```

领域：[用户擅长领域]

高频问题（Top 3-5）：
1. [问题] — 出现次数：X次，现有回答质量：差/一般/好
2. ...

选题建议：
1. [选题名] — 解决[具体问题]，形式：文章/配置包/模板
2. ...

验证动作：
- 写一篇探测器文章发[平台]，看24小时内是否有人追问"能不能直接给我"
- 有人追问 → 立刻做最小产品（配置包/模板/教程），定价29-99元
```

## 小红书专项

### 身份文档（必读）

每次进入小红书写作模式前，先读取身份文档：
`/Users/kuzen/Documents/Obsidian/10-Content Factory/rule/小红书身份文档.md`

**核心身份：** kuzen，帮你从工具焦虑里找回自己的人  
**核心主张：** 你不是缺工具，是缺自己  
**内容公式：** 工具是入口 → 焦虑是钩子 → 身份才是出口  
**核心规则：** 笔记是用来找的，不是用来整理的

**身份与垂直的冲突警告：**
身份卖的是"工具解脱"，但硬垂直 Obsidian 教程卖的是"工具深入"。这两个信号会互相打架：
- 想看教程的人点进来，发现你在说"工具没用"，觉得被耍了
- 想解脱的人关注你，结果你在讲插件配置，觉得你也在制造焦虑

**解决：** 软垂直——借 Obsidian 讲"如何从工具依赖里觉醒"，不是教 Obsidian。

### 选题规则

- **解决问题就写** = 软垂直的核心筛选器
- **评论区找选题 > 搜索找选题**。评论区有真实痛点+情绪（"笔记过千后搜索不到，标签也乱了，崩溃"），搜索只是泛泛的"我想要什么"。
- 刷评论区找选题时，只收集"工具焦虑"类评论（"笔记多了找不到""整理到崩溃""试了无数工具还是焦虑"）
- 跳过"工具怎么配置""哪个功能更好用"类评论——那是硬垂直/教程方向，和身份冲突
- **刷评论区是时间黑洞，必须给硬边界**：只刷 10 分钟 / 只记 3 个选题 / 不点进正文 / 只刷评论区不刷正文
- **没有标准 SOP 找选题**，因为真实需求在评论区，不是关键词搜索能覆盖的

### 标题规则（硬限制）

- **≤20个中文字符**，标点、数字、英文算1格。用户已多次纠正我忘记此限制，必须强制执行。
- **必须有具体产品名或关键词**（Obsidian、Notion、Hermes、Raycast 等），占领搜索流量。
- **标题和 thumbnail 信息对齐**。thumbnail 上的核心卖点必须在标题里出现，避免预期落差。
- 小红书 = **有目的搜索 / 解决生活具体问题**，不是公众号的信息流情绪。
- 个人故事要包装成解决方案，不是纯叙事。

**成功案例：**
- "Obsidian+AI，我放弃了整理笔记"（14字）— 产品名+反常识结论，和 thumbnail"不用花时间整理"对齐，验证通过。

### 竞品调研与差异化定位

当用户要做小红书内容时，先不做脚本，先做竞品调研。这是标题和差异化生死线。

**用户身份锚点：**
- 表层：替你试过所有捷径的人
- 中层：发现工具都在骗我干活
- 底层：你不是缺工具，是缺"够了"的勇气
- 核心定位："够了"系列 — 从工具焦虑里解脱

**内容策略：**
- 不卖工具，卖"替用户试错后的洞察"
- 工具会过时，身份才是资产
- 重点从"推荐工具"转向"我试了多少工具才悟到不用整理"

#### 执行流程
1. **用户提供搜索截图** — 用户在小红书搜索目标关键词，截图结果页给AI
2. **AI分析竞争格局** — 提取每篇的标题、赞数、发布时间、内容类型
3. **识别空白区** — 高赞内容少、情绪高但解决方案缺失的方向
4. **确定差异化** — "别人做了什么，你没做什么，你的机会在哪"
5. **生成标题选项** — 基于爆款规律+差异化，给3-5个标题让用户选

#### 分析维度

| 维度 | 看什么 | 为什么 |
|------|--------|--------|
| 赞数分布 | 哪些方向高赞、哪些低赞 | 判断赛道热度 |
| 同质化程度 | 多少篇在讲同一套东西 | 判断差异化空间 |
| 情绪方向 | 正面安利多还是负面吐槽多 | 判断情绪流量在哪边 |
| 结论明确度 | 标题是否给出明确答案 | 有结论的标题互动率高 |
| 时间分布 | 爆款是近期还是旧内容 | 判断时效性 |

#### 爆款标题规律

**高赞结构：**
- 数字冲突 + 明确结论：`试了47个笔记App，最后只留这1个`（7450赞）
- 身份痛点 + 神器定位：`打工人别折腾了，这1个App够用到退休`
- 反转/情绪释放：`终于不用选笔记App了，就它`
- 年度盘点 + 情绪词：`我的2025年度生产力工具，杠杆力拉满！`

**低赞陷阱：**
- 过程描述无结论：`AI工具那么多，我先替你试一圈`（2赞）
- 纯教程无情绪：`Obsidian官方推荐保姆级实操手册`（144赞）
- 反问无答案：`我舍弃了Notion、Obsidian、flomo选了。。`（308赞，标题没给答案）

#### 差异化空白区识别

从本次会话案例（Obsidian赛道）：
- **红海**：插件推荐（7个必装、30款宝藏、10大热门）
- **蓝海**：`Obsidian放弃`方向 — 高赞（555赞弃坑、275赞折腾不动）但没人给替代方案
- **机会**：`一个就够`定位 — 几乎空白，全是"3个App""8个工具"罗列

#### 标题测试流程

用户有想法后，不要直接写脚本：
1. 把标题给用户去小红书搜
2. 用户截图搜索结果回来
3. AI分析竞争度：类似标题有多少、赞数区间、发布时间
4. 确认差异化足够 → 进入脚本
5. 差异化不够 → 换角度或换标题

**关键原则：标题决定生死，脚本决定留存。标题不对，脚本白写。**

#### 提示词格式（Gemini/nanobanana 专用）

**关键规则：英文主体描述 + 中文文本用引号包裹**

```

```

| 元素 | 处理方式 | 示例 |
|------|---------|------|
| 画面风格/构图/材质 | 全英文描述 | `Hand-drawn notebook style, cream paper...` |
| 图片内要显示的中文文字 | 引号包裹，嵌入英文描述 | `Big bold purple ink text: "不用整理"` |
| 颜色/位置/字体样式 | 英文形容词 | `brush-marker style`, `double underline` |
| 情绪/氛围 | 英文收尾 | `Imperfect authentic handcrafted feel` |

**常见失败：**
| 错误 | 结果 |
|------|------|
| 全中文提示词 | 返回 PNG 文件占位符图标 |
| 中英文混杂描述画面 | 风格偏离，文字渲染错误 |
| 缺少 `9:16` / `vertical portrait` | 生成横版图 |

#### 已验证有效的图类型
1. **痛点场景**：火柴人 + 具体数字 + 焦虑表情
2. **流程图**：箭头连接图标（收件箱→机器人→对话气泡）
3. **封面钩子**：大字标题 + 反常识副标题 + 信任小字
4. **对话截图**：模拟聊天界面，左用户右AI
5. **AI收件箱**：乱纸→箱子→机器人→问答
6. **安全提示**：垃圾桶 + STOP手势 + 底线指令（如"删之前先扔垃圾桶"）
7. **互动引导**：提问式互动，避免客服感（"有问题/评论区交流/你的笔记怎么整理的？"）

## 从"文章引流"到"产品验证"的翻转

用户说"文章用来引导用户购买，然后根据反馈出产品"时，纠正顺序：

**错误顺序**：写文章 → 等反馈 → 出产品（死循环：没有流量就没有反馈）
**正确顺序**：看到需求 → 写探测器文章测试 → 有人买单 → 出产品

探测器文章公式：
- 标题：解决一个具体痛点（越具体越好）
- 内容：给出60%解决方案，留40%在付费产品里
- 结尾钩子："需要完整配置包/模板的朋友可以留言"
- 平台：小红书（新战场）或公众号（老粉丝）

## 陷阱清单

**陷阱0：创建 skill 前未确认**
→ 用户明确说"以后创建 skill 前先跟你确认"
→ 判断标准：有触发条件 + 有执行步骤 + 有输出产物 = 三个都是 yes 才能创建
→ 缺一 → 进 SOUL.md 或 memory
→ 参考：`references/skill-boundary-discipline.md`

**陷阱1：语料库为空时写稿**
→ voice/ 里没有内容 → AI无法提炼风格 → 初稿AI味重
→ 解决：先攒20-30条语料，或从已发布的爆款文章里拆

**陷阱2：rule/ 里没有框架**
→ 第一次用时rule/为空 → AI不知道什么结构有效
→ 解决：先从已发布文章里提炼标题公式和结构，存进rule/

**陷阱3：素材库关键词搜索不到**
→ clip/ 里命名不规范 → grep搜不到
→ 解决：clip文件命名带关键词，如 `clip-bookmark-rate.md` `clip-ai-side-hustle.md`

**陷阱4：用户说"写"但没给平台**
→ 默认按公众号写，但用户可能想要小红书
→ 解决：反问"公众号还是小红书？"

**陷阱5：初稿太长**
→ 用户没给字数限制 → AI写2000字 → 用户嫌长
→ 解决：默认公众号800-1200字，小红书300-500字，除非用户另有要求

**陷阱6：强迫用户做事/用激将法**
→ 用户说"我不喜欢你这种敢不敢的语气，有点激将法的感觉"
→ 用户要的是"找回自己"，不是被推着走
→ 解决：不问"敢不敢""能不能""要不要"，只提供选项，不施压
→ 用户想发就发，不想发就不发，不需要批准或激将
→ **核心原则**：用户要的是被听见，不是被解决

**陷阱7：把日记和语料库分开**
→ 用户问"想法看法记录在哪"，回答"日记里"即可
→ 语料库 = 日记中"有情绪张力的片段"
→ 不需要第二个文档，不需要分类、链接、维护系统
→ 写的时候心里有"这句有刺"就够了

**陷阱8：忘记小红书标题≤20字约束**
→ 用户已明确告知多次，仍生成超长标题
→ 解决：生成小红书标题时主动数字数，>20字立即压缩
→ 优先保留：产品名（英文占字符少）+ 核心动词 + 结果

**陷阱9：用户卡住时给下一步**
→ 用户说"你的问题总是在强迫我去做事"
→ 用户卡住时，可能需要的是梳理思路，不是下一步行动
→ 判断信号：用户连续多轮在谈感受/困惑/回忆，而非问"怎么做"
→ 此时应停止给下一步，只听和回应
→ 区分"要突破卡住"和"要被听见"两种需求
