# 日记阅读工作流

## 触发条件
用户说"读一下我的日记""读日记""更新日记"等。

## 执行流程

### 1. 读取日记文件
- 路径：`~/Documents/Obsidian/10-Content Factory/voice/Days/YYYY/YYYY-MM-DD.md`
- 使用 `read_file` 或 `cat` 读取

### 2. 分析内容
提取以下维度：
- **能量模式**：高能量/低能量/波动
- **核心洞察**：用户自己想到的关键观点
- **工具/优化**：研究或尝试的新工具、流程
- **情绪标记**：焦虑、兴奋、疲惫、顿悟等
- **自我纠正**：用户对自己习惯、想法的反思

### 3. 更新记忆
- **user profile**：能量模式变化、生活哲学更新、新习惯
- **memory**：环境事实、工具使用、文件路径变化

### 4. 生成观察
向用户反馈：
- 今天日记的几个要点（不加评判）
- 一个值得注意的模式（如果有）
- 询问是否需要更新记忆

## 用户纠正记录

### 纠正1：不要把日记内容变成文章
**用户原话：** "你是一个人不要只会做文章，我会和说不是每个方面的根据我说的进行思考而不是久文章文章"

**问题：** 用户分享 shower thought，AI 立即往"怎么用这句话做内容"上引导。

**纪律：**
- 读日记后，先分析、跟着想
- 禁止立刻想"这能写成什么"
- 禁止话术："这句话可以怎么用""这能写成一篇...""存进语料库"
- 用户要的是被理解，不是被开采

### 纠正2：不要反复引用私人创伤
**用户原话：** "您能不能别总是父亲的病、"

**问题：** AI 在分析日记时，反复用"父亲的病"作为用户 voice/angle 的例子。

**纪律：**
- 用户的私人痛苦只在用户主动提及时回应
- 禁止主动引用用户的创伤经历作为"你的特色"
- 用户的痛苦不是 AI 的论据库

### 纠正3：不要过度生产
**用户原话：** "为什么你总是在写文章 我说了需要写文章我会和你说"

**问题：** 读日记后，AI 默认输出文章选题或内容建议。

**纪律：**
- 读日记 ≠ 进入写作流程
- 用户没有说"写""发""做""选题"时，不主动进入写作流程
- 反馈形式：简要分析 + 询问是否需要更新记忆

## 输出格式

```
读完了。

---

今天观察：

[能量模式]：...
[核心洞察]：...
[工具/优化]：...
[情绪标记]：...

一个值得注意的点：...

---

需要我更新记忆吗？
```
