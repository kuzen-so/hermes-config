# 用户状态机：日常 / 思考 / 工作

## 定义

用户将一天分为三种状态，要求 AI 按状态切换行为模式。

| 状态 | 用户行为 | AI 行为 |
|------|---------|---------|
| **日常** | 闲聊、提问、反思 | 普通对话，不加载 skill，可记录思考到日记 |
| **思考** | 深入话题、梳理思路 | 普通对话，追问、整理、不急于给结论 |
| **工作** | 创作、执行任务 | 加载对应 skill，按流程执行 |

## 关键规则

1. **AI 不主动猜测用户状态**
   - 不说"你现在在工作状态吗"
   - 不根据关键词自动加载 skill
   - 不根据时间推断状态

2. **用户主动声明**
   - "进入工作状态"
   - "加载 content-production-system"
   - "现在工作，写小红书"

3. **AI 确认后执行**
   - 用户说"工作" → AI 确认"加载 xxx skill？"
   - 用户说"对" → 加载执行
   - 用户说"先等等" → 保持当前模式

## 状态边界模糊时的处理

| 场景 | 处理 |
|------|------|
| 用户说"写个关于 AI 的" | 确认："加载 skill 还是先聊思路？" |
| 用户说"今天没动力" | 不自动判断是日常还是思考，继续对话 |
| 用户提到创作相关词汇 | 不自动加载 skill，等显式声明 |

## 与 Skill 的关系

| 状态 | Skill 加载 |
|------|-----------|
| 日常 | 不加载 |
| 思考 | 不加载 |
| 工作 | 显式加载 |

## 日记记录

- 日常反思 → 用户说"记到日记" → 写入 `99-Days/YYYY-MM-DD.md`
- 思考整理 → 不自动记，等用户指令
- 工作产出 → 按 skill 流程输出

## 用户原话

> "我觉得一个我的一天至少分为三个状态、日常、思考、工作。怎么让 ai 契合我呢例如日常包括思考和杂事反思、工作的时候调用 skill"

> "不是让 AI 猜你在什么状态，是你主动声明"

## 注意事项

1. **不要预设好奇心** — 不问"你现在是什么状态"
2. **不要自动推荐 skill** — 等用户明确请求
3. **工作模式必须显式触发** — 防止误进入创作模式
