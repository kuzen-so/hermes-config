# Personal Lifestyle Optimization

For users who prefer **subtraction over addition**, **repetition over variety**, and **zero daily decision cost**. Health and image are treated as **integrated production assets**, not separate hobbies.

## Core Philosophy

- **Health is a productivity substrate** — headaches, fatigue, and poor sleep directly destroy earning capacity.
- **Image is a brand asset** — for content creators, visual consistency creates recognition and trust.
- **Zero maintenance** — systems must run on autopilot. No daily choices, no tracking apps, no complex prep.
- **Subtraction over addition** — remove wrong products before adding new ones.
- **Measurement beats estimation** — baseline photos, 7-day weight averages, waist circumference.
- **Identity voting** — each protocol execution is a vote for "I am someone who maintains their appearance."

## Section 1: Body Composition

### Assessment Protocol
1. **Height + weight → BMI** (rough screening only)
2. **Abdominal check**: sit down, count folds
   - 0 folds visible: <15% body fat
   - 1 fold: 16-20%
   - 2+ folds: 21%+
3. **7-day morning weight average** (start today)
4. **Waist at navel**, exhale end
5. **Baseline photos**: front + side, natural light, phone 1.5m away

### Target Setting
- Facial contour improvement typically occurs at 12-15% body fat for men
- From current estimate to target: 1% body fat ≈ 1.5-2 lbs fat loss (muscle constant)
- Time: 8-12 weeks at 1 lb/week fat loss with strength training

### Protocol
- **Diet**: protein-first, 2-3 meals, no food 3 hours before sleep
- **Training**: 3x/week strength, 45 min, compound movements included (not upper-only)
- **Verification**: weekly weight + waist + photo, not daily

## Section 2: Diet Planning

### Step 1: Force Information Disclosure (Non-Negotiable)

| Required Info | Why It Blocks |
|---------------|---------------|
| Wake time (range) | Determines meal timing and count |
| Cooking capacity (self / takeout / convenience) | Determines ingredient list |
| Foods rejected (allergies, disgust, religion) | Prevents plan collapse on day 2 |
| Budget constraint | Filters protein sources |
| Current weight & height | Calculates protein and calorie targets |
| Training history | Determines exercise starting point |
| Sleep regularity | Determines if sleep or diet is the root problem |

**If the user dodges:** Pause. Say "Answer X, or the plan is suspended." Do not proceed with assumptions.

### Step 2: Goal Integration (Merge, Don't Stack)

Users list multiple goals that compete for time. Merge into a single hierarchy:

**Example hierarchy:**
1. Earn money (core)
2. Image (serves earning — video presence)
3. Health (substrate — no headaches, sustained energy)
4. Body composition (result of health actions, not separate goal)

**Rule:** If a "new" goal is actually a sub-item of an existing goal, fold it in. Do not add to the stack.

### Step 3: Build the Minimal Menu

**Principles:**
- Same meals every day. No rotation. No decisions.
- Protein first. Everything else is filler.
- Cooking method: one technique, repeated (boil, pan-fry, or shake).
- Cost per day tracked and minimized.

**Protein Source Selection:**

| Source | Protein/g | Cost/g protein | Prep effort | Palatability |
|--------|-----------|--------------|-------------|--------------|
| Eggs (whole) | 6g/egg | Very low | Boil | High |
| Egg whites | 3.5g/white | Low | Boil or pour | Neutral |
| Chicken breast | 31g/100g | Low | Slice + pan | Low (often rejected) |
| Whey powder | 20-25g/scoop | Medium | Shake | Medium |
| Skinless chicken thigh | 26g/100g | Low | Same as breast | High |
| Lean pork | 26g/100g | Low | Slice + pan | High |
| Tofu | 8g/100g | Very low | Cube + boil | Medium |

**When user rejects a protein source:** Do not argue. Immediately pivot to the next palatable option. Sustainability > optimality.

**Meal Count Decision:**
- Wake before 8:00 + regular sleep → 3 meals
- Wake after 10:00 or irregular → 2 meals, larger
- User explicitly wants fewer decisions → 2 meals if tolerable

### Step 4: Iterate to Convergence

After each modification, restate the full plan with new protein totals. Do not let the user incrementally drift into an unbalanced plan.

### Step 5: Lock and Execute

Final plan format:
```
| Meal | Time | Content | Protein |
|------|------|---------|---------|
| ...  | ...  | ...     | ...     |

Total protein: Xg
Cost/day: ~Y yuan
Prep time: Z min/week

Tomorrow at [TIME]: [FIRST MEAL]. Can you do it?
```

**Do not leave without a binary confirmation.**

## Section 3: Hunger Emergency Protocol

When the user says "I'm hungry" or asks "what should I eat now" — this is NOT menu planning. This is impulse management under degraded decision-making.

### Detection Signals
- User asks "X or Y" repeatedly, escalating carbs
- User asks "is [high-carb food] okay" after already being told no
- User says "I don't think that's enough" despite numbers
- User skips questions about meal timing/positioning

### Response Protocol

**Step 1: Lock the meal's role immediately.**
Ask: "This meal is: (a) delayed lunch, (b) afternoon snack, (c) dinner replacement, (d) tomorrow prep?"

**Step 2: State the hard boundary once.**
If body-composition focused: "No noodles. No fried rice. No combo meals. These are off the table."

**Step 3: Offer the protein-first default.**
From existing stock or nearest available source. Even imperfect protein (roasted chicken at convenience store) beats instant noodles.

**Step 4: Shut down option-circling.**
When user proposes a 3rd+ alternative: "Stop. You are hungry and your decision quality is down. [DEFAULT] is the answer. Execute now."

**Step 5: Force execution, not deliberation.**
"Eat it now. Report back what you actually ate."

### Carb-Emergency Exception
If genuinely crashing (shaking, can't work, no protein available):
- Small carb portion: half a banana, one small bun, or 100g rice
- Must be paired with: "Protein within 2 hours or you crash again."
- This is damage control, not a plan.

## Section 4: Skincare Protocol

### Diagnostic Questions (ask all, no skipping)
1. Morning routine: exact products and order
2. Evening routine: exact products and order
3. Skin type: oily / dry / combination / sensitive
4. Oil timeline: how many hours after cleansing does oil appear?
5. Primary goal: control oil / reduce acne / clear blackheads / minimize pores / even tone
6. Sun exposure: indoor near window? outdoor? sunscreen current status?
7. Current product list with concentrations (e.g., "20% azelaic acid")

### Common Pitfalls
- Oily skin + occlusive moisturizers (squalane, heavy creams) → afternoon oil explosion
- Cleansing too aggressively (foaming/soap-based) → barrier damage → compensatory oil
- Acid without hydration → irritation → worse barrier → worse skin appearance
- No sunscreen with acids → hyperpigmentation
- 补充装无泵头需自行灌装 → 残留旧产品污染、折腾、省的钱不值
- 洁面营销成分（神经酰胺/玻尿酸/美容液）→ 停留30秒冲走，零实际价值
- 限时新客价过期后恢复原价 → 比价时确认是否为常态价

### Adjustment Rules
- **One change at a time**, 3-day verification
- Oily skin: replace occlusives with humectants/light emulsions
- Acid nights: apply acid → wait 10 min → thick moisturizer layer (B5) → 15 min → blot excess → sleep
- **B5 thick mask protocol**: apply white-visible layer, not thin transparent coat; wait 15 min; wipe with damp towel; leave thin residue; do not rinse
- Cleanser: amino acid based for oily skin, not soap/foaming
- **Product idle handling**: occlusive creams (squalane) → save for peeling/winter/body use, not daily face for oily skin
- **Hand hygiene**: dirty hands touch face → bacteria/oil transfer → worse acne and oil

### Product Selection (Frugal Mode)
- 氨基酸洁面：旁氏米粹/芙丽芳丝/多芬泡泡/John Jeff油橄榄慕斯，25-40块，大厂稳定
- 壬二酸：John Jeff 20% 底线；等价升级选希川科颜20%（乳质地更轻薄，刺激更低）
- 防晒：摇摇乐质地，出门必用
- 不为营销成分买单（神经酰胺/玻尿酸/油橄榄在洁面中不驻留）
- 补充装省几毛钱但折腾 → 买正装泵头
- **不囤产品**：用完再买，不提前备货，不追求完美方案先跑起来

### Concentration Selection
- 油皮、耐受、目标"看起来干净" → 20%壬二酸
- 10%/15%仅适合：敏感肌入门、或20%刺激无法耐受
- 已在用20%且无刺激 → 不降级

## Section 6: E-Commerce Shopping (Frugal Mode)

### Comparison Table
| Platform | Spec | Total | Actual Amount | Unit Price | Delivery | Authenticity |
|----------|------|-------|---------------|------------|----------|--------------|
| PDD | 15g | ¥40.5 | 15g | ¥2.7/g | 后天 | 旗舰店 |
| JD | 30g set | ¥84.1 | 40g (30g+5g×2) | ¥2.1/g | 明天 | 自营/旗舰 |

### Decision Factors (in order)
1. **Unit price per gram** — normalize across sizes and gifts
2. **Total cash outlay** — don't overcommit to one product category
3. **Delivery speed** — tomorrow vs day-after matters for protocol start
4. **Authenticity confidence** — flagship store > authorized > unknown
5. **Gift value reality** — labeled ¥77 gift often worth ¥10; ignore or discount heavily

### Pitfalls
- "New customer price" expires, confirm if price is stable
- "Supplement pack" (补充装) without pump → hassle, contamination risk
- Flash sale countdown → urgency is manufactured, price often repeats
- Cross-border bonded warehouse → authentic but slower customs clearance
- **Math errors**: user may miscalculate total grams. Always verify: 规格 × 数量 = 总量
- **Same product, different prices**: screenshots may show same item at different prices (new customer vs regular)
- **Set vs single**: "30g套装" may include samples. Include赠品 in actual amount column

### Supplement Shopping Workflow

**Step 1: Identify the Correct Product Category**

| What They Want | What They Often Land On | How to Check |
|----------------|------------------------|--------------|
| Whey Protein (减脂增肌) | Mass Gainer / Weight Gainer (增肌粉) | Look for "Gainer" or "增肌/增重" in title |
| Whey Isolate (高纯度) | Whey Concentrate (普通乳清) | Look for "Isolate" vs "Concentrate" |
| Pre-workout | Energy drink / BCAA | Check caffeine + beta-alanine content |

**Rule:** If the product title contains "Gainer," "增肌粉," "增重," or "Mass," it is the wrong product for fat-loss/muscle-building goals. Redirect immediately.

**Step 2: Evaluate Price & Authenticity**

| Price Level | Interpretation | Action |
|-------------|---------------|--------|
| ~¥120-150 / 2.2lbs | Suspiciously low | Likely fake, expired, or gray-market |
| ~¥200-250 / 2.2lbs | Normal sale price | Acceptable for MyProtein, 康比特 |
| ~¥350-450 / 5lbs | Normal for ON Gold Standard | Good value per pound |
| >¥500 / 5lbs | Premium/retail | Wait for sale unless urgent |

**Authenticity red flags:**
- "熊猫" in official title (MyProtein's Chinese nickname is not official branding)
- "美国" origin tag on a "英国原装" claim
- 12-year-old store with only 100+ sales
- Price 50%+ below iHerb/official store

**Step 3: Flavor & Format Selection**
- Never recommend unflavored/plain for first-time buyers
- Chocolate > Strawberry > Vanilla > Matcha > Unflavored (safety ranking)
- Buy 1 bag first. Do not bulk-buy until palatability is confirmed.
- Resealable pouch: cheaper, harder to scoop. Tub: easier, slightly more expensive.

**Step 4: Lock Purchase & Set Start Date**
1. Confirm product name, flavor, price, shipping date
2. Set execution start date = delivery date + 1 day
3. List prep tasks before start (buy eggs, prepare cooker, etc.)

## Section 7: Protocol Documentation Split Pattern

When user has multiple concurrent protocols (e.g., diet + skincare + training), **split into separate documents** rather than one combined file.

**Trigger:** User says "拆分" or protocols clearly serve different goals with different verification timelines.

**File structure:**
- `11-Processing/减脂手册.md`
- `11-Processing/护肤手册.md`
- `11-Processing/健身计划.md`
- Each with: 基线、核心原则、流程、产品/动作清单、验证节点、禁忌、关联

**Why split:**
- Different protocols have different verification cycles（护肤3天/8周 vs 减脂4-6周/8-10周 vs 健身每次45分钟）
- Independent execution, no waiting for each other
- Avoids bloated files that are hard to reference quickly

**Content Generation Discipline**

When generating protocol manuals from conversation:
- **Lead with 基线数据**（身高/体重/体脂估算/皮肤类型），用户不必重复输入
- **核心原则 ≤3条**，每条一句话，禁止展开论述
- **流程用表格**，时间+动作，不加解释
- **产品清单只列在用/待换/已停用**，不列"推荐备选"
- **验证节点固定格式：时间+验证内容+通过标准**
- **禁忌用表格，行为→结果**，不说教
- **全文≤300字/篇**，超限强制删

## Section 8: Image Asset Building (for Video/Content Creators)

When the user asks about appearance improvement for content creation:

1. **Determine if image serves earning** — social/dating vs content creation vs self-satisfaction. Path differs.
2. **Identify existing visual anchors** — hair color, facial features, build. Work with what's memorable.
3. **Fix the wardrobe** — 3-4 pieces, same color family, high fabric weight (220g+ T-shirts). No patterns.
4. **Fix the background** — 1-2 shooting locations, consistent. Background is branding.
5. **Fix the light** — window side-light, free and effective.

**Rule:** Consistency creates recognition faster than variety. Wear the same "uniform" in every video for 6 months.

## Pitfalls

- **Assuming user will track anything** — They won't. The plan must be memory-less.
- **Optimizing for perfect macros** — 80g protein executed beats 120g protein planned.
- **Letting the user skip the forced-info step** — Every skipped question produces a failed plan.
- **Adding variety "to prevent boredom"** — Boredom is a smaller risk than decision fatigue.
- **Ignoring sleep regularity** — If sleep is chaotic, diet fixes are secondary.
- **Offering multiple options** — Present one recommended path. If rejected, modify and present one replacement. Never offer A/B/C menus.
- **Explaining marginal benefits of premium products** — When user asks "is it worth the price," answer directly: yes or no. No feature matrices.
- **Skipping the binary commitment** — Every plan must end with "Tomorrow at [TIME]: [ACTION]. Can you do it?"
- **Pressuring the user to start before ready** — When user says "I'll start when X arrives," accept the delay. Do not repeatedly ask "Can you do it?"
- **Letting the user browse the wrong product for 5+ turns** — Intervene immediately if they are on the wrong product page.
- **Engaging with hunger-driven option-circling** — When a hungry user proposes alternatives after you've given the answer, do not analyze the new option. The circling itself is the enemy.
- **Writing plans FOR the user instead of WITH the user** — Provide a template with blanks, force them to fill the first entry, and validate it before proceeding.
