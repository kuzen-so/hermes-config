# Fitness Protocol

## Core Philosophy

- 健康是生产力基底
- 零维护，无每日决策
- 减法优于加法
- 测量优于估算

---

## 1. 身体成分评估

1. 身高+体重→BMI（仅筛查）
2. 坐下数腹部褶皱
   - 0褶皱：<15%体脂
   - 1褶皱：16-20%
   - 2+褶皱：21%+
3. 7天晨起体重平均
4. 肚脐处呼气末腰围
5. 基线照片：正面+侧面，自然光，手机1.5米

**目标**：面部轮廓改善通常需12-15%体脂，8-12周，每周减1磅脂肪。

---

## 2. 饮食计划

### 强制信息披露（不答不建计划）

| 必须信息 | 原因 |
|----------|------|
| 起床时间 | 决定餐时和餐数 |
| 烹饪能力（自炊/外卖/便利） | 决定食材清单 |
| 拒食清单（过敏/厌恶/宗教） | 防计划第二天崩 |
| 预算 | 过滤蛋白来源 |
| 体重身高 | 计算蛋白和热量目标 |
| 训练史 | 决定运动起点 |
| 睡眠规律性 | 判断根因是睡眠还是饮食 |

**用户回避→暂停。** "回答X，否则计划暂停。" 不做假设。

### 目标整合（合并，不堆叠）

示例层级：
1. 赚钱（核心）
2. 形象（服务赚钱）
3. 健康（基底）
4. 身体成分（健康的结果，非独立目标）

**规则**：新目标若是现有目标的子项，折叠进去，不加栈。

### 最小菜单

- 每天同样餐食，不轮换，不决策
- 蛋白质优先，其余是填充
- 一种烹饪技法重复（煮/煎/摇）

**蛋白来源**

| 来源 | 蛋白/g | 每克蛋白成本 | 准备难度 | 适口性 |
|------|--------|-------------|----------|--------|
| 全蛋 | 6g/蛋 | 极低 | 煮 | 高 |
| 蛋白液 | 3.5g/个 | 低 | 煮或倒 | 中性 |
| 鸡胸 | 31g/100g | 低 | 切片+煎 | 低（常被拒） |
| 蛋白粉 | 20-25g/勺 | 中 | 摇 | 中 |
| 去皮鸡腿 | 26g/100g | 低 | 同鸡胸 | 高 |
| 瘦猪肉 | 26g/100g | 低 | 切片+煎 | 高 |
| 豆腐 | 8g/100g | 极低 | 切块+煮 | 中 |

**用户拒一种蛋白→立即换下一个。** 可持续性>最优性。

**餐数决定**
- 8点前起+规律睡眠→3餐
- 10点后起或不规律→2餐，量大
- 用户要更少决策→2餐（如能忍受）

### 收敛锁定

每次修改后重述完整计划和新蛋白总量。不让用户渐进漂移成失衡计划。

### 锁定执行格式

```
| 餐 | 时间 | 内容 | 蛋白 |
|---|------|------|------|
| ... | ... | ... | ... |

总蛋白：Xg
日成本：~Y元
周准备：Z分钟

明天[时间]：[第一餐]。能做到？
```

**必须二元确认，不留开放式结尾。**

## 3. 饥饿应急协议

**检测信号**
- 反复问"X还是Y"，碳水升级
- 问"[高碳水]可以吗"，已被拒绝过
- 说"我觉得不够"，无视数字
- 跳过餐时/定位问题

**响应**

1. **锁定餐的角色**
   "这餐是：(a)延迟午餐 (b)下午加餐 (c)晚餐替代 (d)明天预备？"

2. **硬边界一次**
   减脂期："没有面条、炒饭、套餐。这些不在选项内。"

3. **蛋白优先默认**
   现有库存或最近可得来源。便利店烤鸡也胜过泡面。

4. **终止选项盘旋**
   用户提第3+个替代："停。你饿了，决策质量下降。[默认]就是答案。现在执行。"

5. **强制执行，不讨论**
   "现在吃。吃完汇报实际吃了什么。"

**碳水应急例外**
真崩溃（发抖、无法工作、无蛋白可得）：
- 小份碳水：半根香蕉、一个小包、100g饭
- 必须配："2小时内补蛋白，否则再崩"
- 这是止损，不是计划

## 4. 训练

- 3次/周，45分钟
- 复合动作优先（非只练上肢）
- 验证：每周体重+腰围+照片，非每日

## 5. 补剂购买

### 识别正确品类

| 用户想要 | 常错买到 | 检查 |
|----------|----------|------|
| 乳清蛋白（减脂增肌） | 增肌粉/Weight Gainer | 标题含"Gainer""增肌粉""增重""Mass"→错 |
| 分离乳清（高纯度） | 浓缩乳清 | 找"Isolate" vs "Concentrate" |
| 氮泵 | 能量饮料/BCAA | 查咖啡因+β-丙氨酸含量 |

**规则**：标题含"Gainer""增肌粉""增重""Mass"→立即纠正，这是减脂增肌的错品。

### 价格与真伪

| 价格 | 解读 | 行动 |
|------|------|------|
| ~¥120-150/2.2磅 | 过低 | 可能假/过期/灰市 |
| ~¥200-250/2.2磅 | 正常促销 | MyProtein、康比特可接受 |
| ~¥350-450/5磅 | 正常 | ON金标，每磅值 |
| >¥500/5磅 |  premium/零售 | 等促销，除非急用 |

**真伪红旗**
- 标题含"熊猫"（非官方品牌名）
- "美国"产地标+"英国原装"声称矛盾
- 12年老店仅100+销量
- 价格比iHerb/官方低50%+

### 口味与规格
- 首次不买原味
- 安全排序：巧克力>草莓>香草>抹茶>原味
- 先买1袋，确认适口再批量
- 袋装：便宜，难舀。桶装：易舀，略贵

### 锁定购买
1. 确认品名、口味、价格、发货日
2. 执行开始日=到货日+1天
3. 列到货前准备（买蛋、备锅等）

## Pitfalls

- 假设用户会追踪→他们不会。计划必须无记忆依赖。
- 优化完美宏量→80g蛋白执行胜过120g蛋白计划。
- 让用户跳过强制信息→每个跳过的问题都产出失败计划。
- 加多样"防无聊"→无聊风险小于决策疲劳。
- 忽视睡眠混乱→睡眠乱时饮食修复是次要的。
- 给多选项→给一条推荐路径。被拒则修改后给一条替代。不给A/B/C菜单。
- 解释 premium 产品边际好处→用户问"值不值"直接答是或否，无功能矩阵。
- 跳过二元承诺→每计划结尾"明天[时间]：[动作]。能做到？"
- 用户说"等X到货再开始"→接受延迟，不反复问"能做到？"
- 用户浏览错品5+轮→立即干预。
- 饥饿驱动选项盘旋→不给新选项分析，盘旋本身是敌人。
- 替用户写计划→给模板留空，强制填第一条，验证后再继续。
