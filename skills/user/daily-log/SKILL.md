# Daily Log

## Core Philosophy

- 先存后理，不存就忘
- 不分类，降低记录阻力
- 一行一条，极简格式
- 定期清理（建议每周）

## 记录格式

纯内容，**无时间前缀**。

每条记录前自动空一行，与上一条保持间隔：

```

内容
```

**追加命令**：
```bash
printf "\n\n内容" >> "98-Days/YYYY/YYYY-MM-DD.md"
```

## 存放位置

默认：`98-Days/YYYY/YYYY-MM-DD.md`

即 Obsidian 当天的日记文件。

**自动创建**：如果当天日记不存在，自动创建文件并写入。使用 `mkdir -p` 创建目录，`touch` 创建文件。

## 使用方式

用户说"记一下"，直接追加到 inbox 文件。不追问分类、不追问优先级。

## 对话总结模式（Conversation Summary）

当用户说"总结"时，回顾当前对话上下文，按主题切分。

**一段对话 = 一件事 = 一篇。两件事 = 两篇。**

**拆篇信号（强制）：**
- 用户说"还有一件事""另外""换个话题"
- 上下文明显切换主题（从 A 改到 B）
- 用户明确说"这是另一件事"

不判定"有没有认知突破"，只判定"做了什么"。

**口头确认 ≠ 执行。** 当总结需要生成文件时，必须立即调用 write_file，不能只说"生成到 X"而不写。

**多平台数据聚合（日报/总结前置步骤）：**
用户的主要交互发生在微信（Weixin gateway），CLI 是次要入口。生成日报或总结时，必须从**两边**收集数据：
1. **CLI 端**：检查 Obsidian 日记文件（`99-Days/YYYY/YYYY-MM-DD.md`）
2. **微信端**：查询网关日志（`~/.hermes/logs/gateway.log`）提取当天所有 `inbound message`
   - 用 `grep "YYYY-MM-DD" gateway.log | grep "inbound message"` 获取时间线
   - 用 `awk -F'msg='` 提取用户原话
   - 两条管道状态不共享，不可互相替代

**禁止行为**：只查日记文件就判定"今天为空"——日记可能空白，但微信端有大量对话。

**正确流程**：
1. 读取 Obsidian 日记（如有）
2. 读取 gateway.log 当天记录
3. 合并时间线，按 HH:MM 排序
4. 生成日报/总结

### 做了什么

区分输入（看了/听了/读了）和输出（写了/做了/决定了）。

### 关闭状态

- **已解决**：正向关闭 / 证伪 / 淘汰 / 合并
- **未解决**：仍在阻塞

### 路径

| 状态 | 存放位置 |
|---|---|
| 已解决 | `98-Logs/` |
| 未解决 | `01-To do/99-Question/` |

### 文件名

`YYYY-MM-DD-来源-核心问题.md`

**冲突处理**：同一天同来源同问题，末尾加 `-01` 递增。

示例：`2026-05-01-Hermes-input-output重构.md`

---

### 已解决模板

```markdown
# YYYY-MM-DD-来源-核心问题

## 做了什么
- [输入：导致行动的信息]
- [输出：实际产出的结果]

## 关键判断
[关闭类型：解决/证伪/淘汰/合并。一句话说明为什么到此为止。]

## 策略
[只有1条：此刻重来会优先做的决策。不是待办，是认知。]

## 关联日记
[[YYYY-MM-DD]]
```

### 未解决模板

```markdown
# YYYY-MM-DD-来源-核心问题

## 做了什么
- [输入：导致卡住的背景]
- [输出：实际尝试过的动作及结果]

## 卡在哪
[阻塞类型：信息/能力/决策/外部。一句话，最底层阻塞点。]

## 下一步验证
[只有1条。格式：做X，验证Y假设。]

## 关联日记
[[YYYY-MM-DD]]
```

---

### 规则

1. **时间**：只用绝对日期 `YYYY-MM-DD`。禁用今晚/昨天/明天。
2. **清单**：不列未来待办。只留此刻认知和下一步最小动作。
3. **字数**：全文不超过300字。超限强制拆篇。
4. **原创**：不存他人原句、不存AI生成原文。引用必须转述后删除原句。
5. **所有权**：只留自己的判断和 output。
6. **维护**：不整理、不维护、不设标签。写完即埋。

```
水杨酸今天泛红，可能是天气热屏障变薄

skill 触发模式：消息、Command、定时、Webhook

```

## Pitfalls

- 追问"放哪个分类"→不分类，直接存 inbox
- 追问"重要吗/紧急吗"→不判断，先存
- 整理成瘾→每周清一次，不是每次记完就整理
- **路径变更**：用户已将日记路径从 `1-Inbox/log.md` 改为 `98-Days/YYYY/YYYY-MM-DD.md`，必须遵守，不可回退到默认路径
- **自动创建**：如果当天日记文件不存在，必须自动创建（`mkdir -p` + `touch`），不能报错或让用户手动创建
