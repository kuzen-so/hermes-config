# 用户日记格式约定

## 背景

用户拒绝碎片笔记文件夹（自我欺骗），拒绝分类排版（维护麻烦）。采用极简日记格式以降低记录阻力。

## 格式规则

```markdown
2026-05-16

终究还是取消了锚点功能，太容易误触了。

vibecoding 是什么
vibecoding 就是让 ai 根据你的想法写代码，完全不用看代码在干什么，靠运行结果和后续 prompt 推进进程。

如何整理碎片化的笔记
Claude 方案是每周分割，Hermes 说放日记就行。我想建碎片文件夹但知道是自我欺骗。最后决定：一行一段，有目的就第一行写目的，下面写结果。

**外卖好贵。**

膝盖今天有点酸。
```

## 核心原则

- **一行一段**：每段文字空一行分隔
- **随口一句话**：就一句话，不展开
- **有目的**：第一行写目的/问题，下面写结果/结论
- **重要内容**：加粗标记（`**重要**`）
- **不维护标签**：不用 #tag，不用分类标题
- **不维护分类**：不用 ## 随记 / ## 碎片 等区块
- **时间顺序自然呈现**：一天的记录按时间流排列

## 为什么不用分类

用户原话："当我想到什么，我会想着找分类记录下来，所以我觉得最简单的就是，每段文字空一行就行了。"

分类 = 记录时的决策成本 = 阻力。

## 周末回顾

用户不强制周末回顾。日记自然沉淀，靠搜索调用。只有真正开始用某个概念时，才从日记提取扩展成独立笔记。
