# Butler — 管家

日常管理集合。覆盖记账、日志、健身、护肤四个场景。

## 备忘录资料库

管家维护以下 Apple 备忘录，用于长期跟踪：

| 备忘录 | 用途 | 更新触发 |
|--------|------|---------|
| 💰 账单 | 记账明细 | 用户说"花了""收入" |
| 💪 训练记录 | 健身反馈（含身体数据、饮食计划、训练日志） | 用户反馈训练数据 |
| 🧴 护肤记录 | 护肤反馈（含皮肤类型、产品清单、反应记录） | 用户反馈皮肤状态 |

**信息拆分规则**：
- 身体数据（身高/体重/体脂）→ 💪 训练记录
- 皮肤类型 → 🧴 护肤记录
- 不保留独立的"形象提升基础档案"

**追加格式**：无时间前缀，每条前空一行。详见 `references/memo-update-patterns.md`。

**备忘录 vs Obsidian 分工**：
- 训练/护肤/记账记录 → Apple 备忘录（手机查看，长期跟踪）
- 日常碎片/询问总结 → Obsidian 日记（日记流，事后回顾）

## 包含子 Skill

| 场景 | 触发词 | 调用 |
|------|--------|------|
| 记账 | 记账、花了、收入、预算 | 写入备忘录「💰 账单」 |
| 日志 | 记一下、记下来、先存着、日志 | `skill_view('daily-log')` |
| 健身 | 减脂、增肌、饮食、训练、蛋白粉、体重、饿了 | 参考 lifestyle-protocol Protocol A，反馈写入备忘录「💪 训练记录」 |
| 护肤 | 护肤、洗面奶、壬二酸、防晒、脸油、长痘、脸痒 | 参考 lifestyle-protocol Protocol B，反馈写入备忘录「🧴 护肤记录」 |
| 询问 | 问你、有个问题、问一下、请教 | 搜索实时信息→直接答复→结束判定→总结写入当天日记 |

## 使用方式

用户直接说需求，无需切换 skill。Agent 根据关键词自动加载对应子 skill。

## 规则

- 不重复创建已存在的子 skill
- 子 skill 更新时，管家 skill 自动继承最新内容
- 微信路由触发后，保持当前上下文直到用户明确切换话题
- **询问场景完整工作流**：
  1. 用户提问 → 判断是否需要搜索（事实类/时效类问题用搜索，观点类直接答）
  2. 搜索获取实时信息 → 整合答复
  3. **结束判定**（满足任一即结束）：
     1. 用户说"没事了""谢谢""就这样""懂了"
     2. 用户切换到其他话题（记账/健身/护肤）
     3. 用户明确说"记录一下"
     4. **超过3分钟没有继续询问** → 下次用户发消息时，先写总结再处理新请求
  4. 问题结束后 → 将问答总结写入当天 Obsidian 日记
  5. **总结格式**：`询问总结：[问题简述]\n- [要点1]\n- [要点2]`
- **执行逻辑**：Agent 在上下文中维护 `last_question_time`，每次用户询问时更新。下次用户发消息时，若时间差 > 3分钟且上一条是 Agent 的回复，视为问题结束，先执行总结写入，再处理新请求。
- **集合型 skill 的增删规则**：
  - 添加子 skill：用户明确要求时添加，更新 triggers 和表格
  - 移除子 skill：用户明确要求时移除，同步更新 triggers 和表格
  - 子 skill 独立存在时，管家 skill 只负责路由，不复制其内容
- **集合型 skill 的边界**：管家只负责路由，不复制子 skill 内容。子 skill 的更新自动生效，无需同步修改管家
  - 例外：子 skill 的 triggers 变更可能影响管家路由表，需手动同步
- **删除子 skill 流程**：用户要求删除 → 从 triggers 和表格中移除 → 清理关联的备忘录（询问用户是否保留）
- **周报 weekly-report 已独立**：说"周报"时不经过管家，直接加载 weekly-report
- **预算追踪器 budget-tracker 已删除**：记账功能由管家直接写入备忘录「💰 账单」，不再引用独立 skill
