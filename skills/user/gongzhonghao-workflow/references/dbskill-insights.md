# dbskill 借鉴笔记

来源：dontbesilent2025/dbskill GitHub 仓库（4.9k stars）

## 核心值得借鉴的设计

### 1. 消解问题 ≠ 回答问题
- dbs-diagnosis 的核心哲学：99.1% 的问题在 5 层消解漏斗里消失
- 5 层：语言陷阱 → 假设错误 → 逻辑错误 → 事实前提 → 信息充分性
- 每层都停下来对话，不闷头跑分析

### 2. 技能自动推荐链路
- diagnosis 发现方向对了但缺路径 → 自动推荐 benchmark
- benchmark 找到对标后 → 自动推荐 content
- content 发现开头问题 → 自动推荐 hook
- 不是等用户问，是诊断完主动推下一步

### 3. 状态管理三件套
- /dbs-save：存档诊断结论
- /dbs-restore：下次续上
- /dbs-report：合并多次存档成报告
- 诊断不是单次问诊，是持续过程

### 4. 说话风格纪律
- 直接到刺痛，不铺垫不委婉
- 每一步都对话，做完一层抛结论等回应
- 绝对不做：说"每个人的情况不同"、推荐"去做市场调研"、用"赛道""行业"词

### 5. 知识库完全开放
- 4176 个知识原子（JSONL，带主题标签）
- 10 个 Skill 知识包（框架 + 案例库）
- 可单独取用，不需要装整套

## 可融入现有 workflow 的点

| dbskill 设计 | 对应到现有 workflow |
|-------------|-------------------|
| 消解漏斗 | 选题前增加"问题是否成立"判断 |
| 自动推荐链路 | 竞品调研后自动推内容诊断 |
| 状态管理 | 发布检查清单后增加存档动作 |
| 内联案例库 | SKILL.md 里嵌入已验证案例 |
| 前提挑战（YC office-hours 式） | 诊断报告结尾强制给"明天第一件事" |

## 小红书标题公式对比

| dbs-xhs-title（75个公式） | 现有 workflow |
|--------------------------|--------------|
| 12 类心理触发器分类 | 按平台差异分类 |
| 每个公式附原始爆款举例 | 只有公式无举例 |
| 公式匹配器，必须追溯到编号 | 自由发挥 |
| 标题质量 5 条铁律 | 只有≤20字限制 |

差距：现有 workflow 的标题生成太自由，建议参考 dbskill 的"公式匹配器"思路。
