# dbskill 借鉴笔记

来源：dontbesilent2025/dbskill GitHub 仓库（4.9k stars）

## 核心值得借鉴的设计

### 1. 消解问题 ≠ 回答问题
- dbs-diagnosis 的核心哲学：99.1% 的问题在 5 层消解漏斗里消失
- 5 层：语言陷阱 → 假设错误 → 逻辑错误 → 事实前提 → 信息充分性
- 每层都停下来对话，不闷头跑分析

**应用到小红书 workflow：**
- 用户说"想写一篇关于XX的" → 先问"这个问题值得写吗？"（竞品调研=第一层消解）
- 不要直接给脚本

### 2. 技能自动推荐链路
- diagnosis 发现方向对了但缺路径 → 自动推荐 benchmark
- benchmark 找到对标后 → 自动推荐 content
- content 发现开头问题 → 自动推荐 hook
- 不是等用户问，是诊断完主动推下一步

**应用到小红书 workflow：**
- 竞品调研完成（diagnosis）→ 自动进入标题公式匹配（benchmark）→ 确认后进入脚本（content）
- 条件路由已实现此链路

### 3. 状态管理三件套
- /dbs-save：存档诊断结论
- /dbs-restore：下次续上
- /dbs-report：合并多次存档成报告
- 诊断不是单次问诊，是持续过程

**应用到小红书 workflow：**
- 发布检查清单完成后 → 建议存档（标题/数据/复盘要点）
- 下次同类选题 → 调用存档对比

### 4. 说话风格纪律
- 直接到刺痛，不铺垫不委婉
- 每一步都对话，做完一层抛结论等回应
- 绝对不做：说"每个人的情况不同"、推荐"去做市场调研"、用"赛道""行业"词

**已融入 SKILL.md "说话风格"章节**

### 5. 知识库完全开放
- 4176 个知识原子（JSONL，带主题标签）
- 10 个 Skill 知识包（框架 + 案例库）
- 可单独取用，不需要装整套

**对应到现有 workflow：**
- 标题公式库 = 知识包
- 案例库 = 知识原子
- 条件路由 = 自动推荐链路

## 关键差距（仍待改进）

1. **无状态存档机制** — 每次对话独立，无法续上上次诊断
2. **无知识原子库** — 案例库只有2个，需持续积累
3. **无自动消解漏斗** — 竞品调研是手动步骤，非自动触发
4. **无 /save /restore 命令** — 用户无法主动存档
