# Skill 编写指南

来源：从 dbskill 结构 + 用户实践提炼

## 一个 skill 的标准结构（7 个模块）

```
Frontmatter → 身份定位 → 核心公理 → 执行流程 → 案例库 → 说话风格 → 条件路由
```

### 1. Frontmatter
```yaml
---
name: skill-name
description: |
  一句话描述这个 skill 做什么。
  触发方式：/命令、关键词
trigger: 用户说"XX""YY"时自动加载
---
```

### 2. 身份定位
- 你是谁
- 核心工作不是 X，是 Y（一句话差异化）

### 3. 核心公理（2-6 条，非谈判项）
- 所有判断的源头
- 用"公理"而不是"建议"——不可谈判
- 每条公理一句话解释

### 4. 执行流程（Phase 1→2→3）
- 每步有明确输入输出
- 关键原则：每一步都停下来对话，不闷头跑完
- 诊断类 skill：用漏斗/检测逐层过滤
- 执行类 skill：用检查清单确保不遗漏

### 5. 内联案例库
- 典型案例：成功做法 + 诊断要点
- 反面案例：失败做法 + 诊断要点
- 案例比规则更有用——训练判断力

### 6. 说话风格
- 该做什么（3-5 条）
- 绝对不做（3-5 条，用"不要"开头）

### 7. 条件路由
- 什么时候推荐下一个 skill
- 不是每次都推荐，只在明确指向时

## 关键设计决策

| 决策 | 说明 |
|------|------|
| 每个 skill 只做一件事 | 有明确边界，不做路由表之外的事 |
| 消解问题优先于回答问题 | 诊断类 skill 的核心 |
| 每一步都对话 | 做完一层抛结论等回应 |
| 案例库 > 抽象规则 | 案例训练判断力，规则训练 obedience |
| 条件路由自动推荐 | skill 之间形成链路，不是孤岛 |

## 常见 skill 类型

| 类型 | 结构特点 | 例子 |
|------|---------|------|
| 诊断类 | 消解漏斗/检测框架 + 案例库 | dbs-diagnosis |
| 执行类 | 检查清单 + 步骤流程 | xiaohongshu-workflow |
| 工具类 | 公式库/模板库 + 匹配逻辑 | dbs-xhs-title |
| 状态类 | 存档/恢复/报告 | dbs-save/restore/report |

## 用户特定纪律

- 创建 skill 前必须问"这个配做 skill 吗？"
- 文件缺失时不自动重建
- 日常聊天不加载 skill，工作需要时显式加载
